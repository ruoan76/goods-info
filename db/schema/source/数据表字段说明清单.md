## 二、mdm_goods — 商品主表

| 6 | category_confidence | double precision | YES | — | 分类置信度 0~1。受 CHECK 约束 |
| 7 | unit_id | text | YES | — | 计量单位编码，如 `000004` |

| 9 | outprice | numeric | YES | — | 销售价。受 CHECK 约束 ≥0 |

### 2.3 decision_trace 结构

**类型是 text，存的是 JSON 字符串。查询时必须转换：**

```sql
-- 正确
SELECT (decision_trace::jsonb -> 'CATEGORY' ->> 'v') FROM mdm_goods;

-- 错误（报错 operator does not exist: text -> unknown）
SELECT decision_trace -> 'CATEGORY' FROM mdm_goods;
```

**字段结构：**

```json
{
  "GOODS_NAME": {"v": "湿巾", "src": "merged_csv", "rule": "MODE"},
  "UNIT_ID":    {"v": "000004", "src": "merged_csv", "rule": "MODE"},
  "INPRICE":    {"v": 1.0, "src": "merged_csv", "rule": "MODE"},
  "OUTPRICE":   {"v": 2.0, "src": "merged_csv", "rule": "MODE"},
  "CATEGORY":   {"v": "C0405", "src": "merged_csv", "rule": "MAPPING"}
}
```

**已知陷阱：3,211 行含 `|` 字符，是不合法 JSON，`::jsonb` 会报错。**

```sql
-- 必须加过滤
WHERE decision_trace NOT LIKE '%|%'
```

### 2.4 索引与约束

| 名称 | 定义 |
|---|---|
| mdm_goods_pkey | PRIMARY KEY (barcode) |
| idx_g_category | btree (category_id) |
| idx_g_grade | btree (quality_grade) |
| idx_g_batch | btree (governance_batch) |

```
ck_goods_conf    : category_confidence IS NULL OR (0 <= x <= 1)
ck_goods_grade   : quality_grade IN (A, B, C, D)
ck_goods_price   : inprice >= 0 AND outprice >= 0
ck_goods_qscore  : quality_score IS NULL OR (0 <= x <= 100)
ck_goods_source  : category_source IN (MAPPING, AI_FILLBACK, SEMANTIC_FIX,
                                       UNCLASSIFIED, ANCHOR_RULE, MANUAL)
ck_goods_status  : status IN (ACTIVE, INACTIVE, VOIDED)
ck_goods_ver     : version >= 1
```

## 三、mdm_category — 分类树

**174 行，12 列**

| # | 字段 | 类型 | 可空 | 默认 | 说明 |
|---|---|---|---|---|---|
| 1 | **category_id** | text | NO | — | **主键**。如 `C01`（L1）、`C0101`（L2） |
| 2 | **parent_id** | text | YES | — | **父节点**。L1 为 NULL，L2 指向 L1 |
| 3 | **category_level** | integer | NO | — | **层级**。实际只有 1（13 个）和 2（161 个） |
| 4 | **category_path** | text | NO | — | **完整路径**。如 `/C01/C0101/`，用于递归查询 |
| 5 | **category_name** | text | NO | — | **分类名称**。如「休闲零食」 |
| 6 | **external_code** | text | YES | — | **外部编码**。对应上游 ODS 的 `SORT_ID`，如 `03000001` |
| 7 | is_leaf | integer | NO | 1 | 是否叶子。1=叶子可挂商品，0=非叶子 |
| 8 | sort_order | integer | NO | 0 | 排序号 |
| 9 | attr_template_id | text | YES | — | 属性模板 ID。**当前 10 个是空串而非 NULL** |
| 10 | quality_grade | text | YES | — | 分类质量等级（未启用） |
| 11 | status | text | NO | `'ACTIVE'` | ACTIVE（165）/ DEPRECATED（9） |
| 12 | version | integer | NO | 1 | 版本号 |

### 3.1 层级分布

| category_level | 数量 | is_leaf | 说明 |
|---|---|---|---|
| 1 | 13 | 0 | L1 域 |
| 2 | 161 | 1 | L2 叶子 |

**当前只有两层。161 个 L2 里，103 个是卷烟品牌，9 个是 DEPRECATED 的编码僵尸，真正品类叶子 49 个。**

### 3.2 external_code 解码规律

**这是理解分类树来源的关键：`external_code` 前 6 位能还原上游 POS 的分组。**

| 码段 | 节点数 | 映射到 |
|---|---|---|
| 030000 | 11 | C01 食品(7) + C09 饮料(4) |
| 030001 | 6 | C02 酒类(5) + C00(1) |
| 030002 | 6 | C03 生鲜冷品 |
| 030003 | 12 | C04 家居用品(9) + C00(3) |
| 030004 | 5 | C05 母婴玩具 |
| 030005 | 3 | C06 文具礼品 |
| 030006~030011 | 103 | C07 卷烟品牌 |
| 030020/030030/030040/030063 | 9 | C00 僵尸桶 |
| 800010/800011/800012 | 6 | C10 / C11 / C12（后期自建） |

**结论：C01~C07 是 1:1 照抄上游 POS 分类码，C10~C12 是我们后期自建的。**

## 七、数据类型陷阱汇总

**这张表是本清单最实用的部分，每个坑都实际踩过。**

| # | 陷阱 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | `decision_trace` 是 **text** 不是 jsonb | `->` 操作符报错 | `(decision_trace::jsonb -> ...)` |
| 2 | `decision_trace` 有 3,211 行含 `|` | `::jsonb` 转换报错 | 加 `WHERE decision_trace NOT LIKE '%|%'` |
| 3 | `created_at` / `updated_at` 是 **text** | 时间比较按字符串 | 或 `::timestamptz` 转换 |
| 4 | `sys_gov_batch.started_at` / `finished_at` 是 **text** | 同上 | 同上 |
| 5 | `mdm_goods_history.batch_id` 有外键 | 直接插 history 报错 | 先在 sys_gov_batch 登记 |
| 6 | `mdm_goods.governance_batch` 是 **NOT NULL** | 回滚时设 NULL 报错 | 必须有 old_batch 可还原 |
| 7 | `mdm_category.attr_template_id` 有空串 | `IS NULL` 查不到 | 用 `IS NULL OR = ''` |
| 8 | `mdm_goods_history.field_name` 有两种写法 | 统计漏算 | `category_id` 和 `CATEGORY` 都要算 |
| 9 | `category_path` 需带首尾斜杠 | LIKE 匹配失败 | `LIKE '/C01/%'` |
| 10 | `is_leaf` 是 integer 不是 boolean | `WHERE is_leaf` 报错 | `WHERE is_leaf = 1` |

## 八、字段与上游 ODS 的对应关系

**上游数据结构文档 `ods_lx_grtdb_pub_goodsinfo数据结构.xlsx` 共 33 个字段，我们用了 7 个：**

| ODS 字段 | 中文名 | 说明 | 映射到 |
|---|---|---|---|
| GODS_ID | 商品编码 | 36 位随机码 | ❌ 未使用 |
| SECOND_ID | 行业内码 | — | ❌ 未使用 |
| **GODS_NAME** | **商品名称+规格** | 必填 | **mdm_goods.goods_name** |
| **SHORT_GODS_NAME** | **商品简称** | 默认同商品名，客户可改 | ❌ **未使用（16,723 行有中文可回退）** |
| **GODS_SPELL** | **拼音码** | 名称汉字首字母自动生成 | ❌ **未使用（1,824 行被误当作商品名）** |
| **SORT_ID** | 分类 | 关联分类表 | **mdm_category.external_code** |
| **BARCODE** | 条形码 | 必填 | **mdm_goods.barcode** |
| UNIT_ID | 单位 | — | mdm_goods.unit_id |
| INPRICE | 进货价 | — | mdm_goods.inprice |
| OUTPRICE | 销售价 | — | mdm_goods.outprice |

**关键：`GODS_NAME` 是「商品名称+规格」，`GODS_SPELL` 才是快捷输入用的拼音码。**
**当前 1,824 行存的是 `GODS_SPELL`，属于取错列。**

## 九、本清单的验证方法

```sql
-- 字段定义
SELECT column_name, data_type, character_maximum_length, is_nullable, column_default
FROM information_schema.columns WHERE table_name = 'mdm_goods' ORDER BY ordinal_position;

-- 约束
SELECT conname, pg_get_constraintdef(oid) FROM pg_constraint
WHERE conrelid = 'public.mdm_goods'::regclass;

-- 实际取值分布
SELECT category_source, count(*) FROM mdm_goods GROUP BY 1 ORDER BY 2 DESC;
```

**全部字段说明来自 information_schema 实测，非文档抄写。**
