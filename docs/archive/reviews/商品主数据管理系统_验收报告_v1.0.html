二、操作手册 · 业务员（录入员 Operator）

1. 登录

打开 http://10.16.2.43:8090/ → 输入账号 operator / 密码 Mdm@2026（首次登录建议修改）→ 登录。右上角显示角色「录入员」，管理后台菜单不可见。

2. 建档（新品引进）

第一步 · 两段式查重：工作台 →「新增商品」→ 填条码 + 商品名称 →「开始查重」。系统做条码命中（BLOCK 拒建）+ 同名命中（WARN 提示）；三态结果即时显示。
第二步 · 填档案：查重通过后选分类、单位、进价、售价 →「确认建档」。条码建档后不可修改。

3. 改商品 / 补价

商品档案页左边选分类、右边看商品，可按条码/名称查询 → 点进详情 → 点价格/名称即变输入框，改完回车保存，自动留痕。工作台「价格待补」入口可逐条补价，填一个少一个。

4. 批量导入 / 导出

新增商品页切到「批量导入」→ 下载 CSV 模板 → 填写 → 上传校验（500 行/批事务，失败行清单可查）。导出在商品档案/工作台按钮，上限 20 万行，行为记入日志。

管理员（Steward）额外操作

分类与属性模板：管理后台 →「分类与属性模板」→ 选类目 → 调整影响分析 / 外部码对照 / 设置属性模板（JSONB，Steward 权限）。
条码管理：条码校验（格式+禁复用+别名+书号四检查）、换码登记、别名归并。
用户管理：统计卡、查询筛选、点行看详情抽屉（基本信息/权限/活动）、新增/编辑、启停、重置密码。
商品停用/作废：详情页管理员可见「停用/作废」按钮；作废后条码 90 天禁复用；状态反向流转被 3007 拒绝。

六、D13 终验发现并修复的真实缺陷

隐藏 bug：所有 pydantic 校验失败曾返回 500 而非 422。
  • 现象：PATCH 传非法字段（如 barcode）或任何请求体校验失败时，返回 code=5000 服务端异常 而非契约规定的 422。
  • 根因：validation_handler 的 exc.errors() 在 pydantic v2 下 ctx.error 是 ValueError 对象，json.dumps 无法序列化 → 处理器自身抛 500。
  • 修复：① 新增 _jsonable() 把异常对象降级为字符串；② PatchBody 白名单从 4 字段扩到与铁律②一致的 8 字段（barcode 仍永久拒绝）。
  • 复验：改 barcode → 422 + 明确错误信息；合法字段 → 200；35 pytest + 37 项最终全链路全绿，无回归。
此缺陷在 D2~D6 单测中未暴露（测试未覆盖非法字段），由 D13 经 nginx 真实 HTTP 全链路扫出并根治。
